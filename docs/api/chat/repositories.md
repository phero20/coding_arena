# Chat Repository

The Chat module utilizes PostgreSQL to permanently store the conversational history between the user and the AI. It uses **Drizzle ORM** for type-safe query building.

**File**: [api/src/repositories/chat/chat.repository.ts](../../../api/src/repositories/chat/chat.repository.ts)

## Schema Definitions

The repository operates on two main tables defined in `api/src/db/schema.ts`:

1. **`chatThreads`**
   - Represents a single continuous conversation session.
   - Tied via foreign key to a specific `diagramId`.
   - Contains a `title` (often auto-generated by the AI or derived from the first prompt).
   - Tracks `updatedAt` to easily sort a user's recent chats.

2. **`chatMessages`**
   - Represents an individual message within a thread.
   - Tied via foreign key to `threadId`.
   - Has a `role` enum (`"user"`, `"assistant"`, `"system"`).
   - Contains the raw markdown `content`.

## Repository Methods

### Thread Management
- **`createThread`**: Uses `.insert().returning()` to spawn a new conversation.
- **`findThreadById`**: Fetches a single thread based on ID for validation purposes.
- **`findThreadsByDiagramId`**: Fetches all threads for a specific System Design diagram, sorting by `updatedAt DESC` so the most recently active chats appear first.
- **`touchThread`**: A utility method that updates a thread's `updatedAt` timestamp. The `ChatService` calls this every time a new message is sent to keep the thread at the top of the user's sidebar.
- **`deleteThread`**: Permanently removes a thread and cascades the deletion to all its messages.

### Message Management
- **`createMessage`**: Inserts a new user prompt or AI response into the database.
- **`findMessagesByThreadId`**: Fetches all historical messages for a thread, sorting by `createdAt ASC` so they appear in chronological conversational order. This method is used primarily when the Redis cache suffers a miss and needs to repopulate the sliding window.
